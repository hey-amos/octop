# 二次开发记录

这里记录 `hey-amos/octop` 相对上游 `TencentCloud/Octop` 的定制工作，包括设计决策、功能与修复、同步上游时的适配，以及定制版发布说明。

本目录随 `feature/*`、`develop` 和 `release/*` 维护，不进入镜像 `main`。上游原有文档继续跟随上游更新，fork 专属说明集中在这里。

## 入口

- [AGENTS.override.md](../../AGENTS.override.md)：Codex 的 fork 规则入口，并要求读取上游 `AGENTS.md`。
- [develop-fork](../../.agents/skills/develop-fork/SKILL.md)：开发、rebase、发布冻结和修复回流步骤。
- [sync-upstream](../../.agents/skills/sync-upstream/SKILL.md)：上游 main 和原始标签同步步骤。

规则和操作步骤由上述文件维护；本目录重点记录做了什么、为什么做及结果，避免复制整份技能造成多处维护。

## 记录方式

- 一项相关改动维护一篇 `changes/YYYY-MM-DD-主题.md`，以开始记录的日期命名；日期使用项目协作时区 `Asia/Shanghai`。继续完善同一项工作时更新原记录，不按每次对话或提交拆分。
- 有实质影响的功能、修复、架构或流程决策，以及上游升级适配，随实现一起更新记录和下方索引。仅查看状态、无变化的同步或小型文字纠错不要求单独建档。
- 写清基于哪个上游版本和提交、修改原因、实现范围、验证结果，以及以后同步上游时需要关注的地方。区分已决定、已实现、已验证、已发布；未执行的事项不能写成已完成。
- 记录保持简短，可省略不适用的段落。已知时附 PR 或发布标签；开发分支的提交 SHA 可能被 rebase 改变，不把它作为唯一索引，也不编造尚未产生的提交或发布链接。
- 不记录密钥、凭据或无关本机信息。Git common-dir 下的 `develop-fork/*.json` 是本地操作与恢复记录，不会随克隆分发，也不能替代这里的共享文档。
- 定制版发布时，在对应记录中补充实际标签、上游基线、制品和验证结果；后续记录增多再按需要增加发布索引，不预建空目录。

新记录可沿用以下结构，并按实际内容裁剪：

```markdown
# 改动标题

- 日期：
- 状态：
- 上游基线：标签（如适用）及提交 SHA
- 关联：功能分支、PR 或发布标签（已知时填写）

## 背景与决定
## 实现范围
## 验证结果
## 上游同步注意事项
## 未完成事项
```
